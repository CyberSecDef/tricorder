# Development certificates

Generated by `npm run certs` (`scripts/make-certs.sh`). **This whole directory
is gitignored** — the private keys must never be committed.

| File | What it is |
|---|---|
| `ca-cert.pem` | The development CA. This is the file you install on the phone. Public. |
| `ca-key.pem` | The CA private key. Never leaves this machine, never served. |
| `server-cert.pem` | Leaf certificate for this machine's hostname and IPs. |
| `server-key.pem` | Leaf private key, read by `vite.config.ts`. |
| `san.cnf` | Generated SAN list — regenerated on every run. |

`npm run serve-ca` serves **only** `ca-cert.pem`, over plain HTTP, from a
temporary directory. It has to be HTTP: the phone cannot trust our HTTPS origin
until it has already installed this certificate, so bootstrapping over TLS
would be circular.

Why this exists at all: iOS refuses motion, orientation, geolocation and
`getUserMedia` outside a secure context, and a phone cannot reach `localhost`.
Over plain HTTP those APIs fail silently rather than throwing (§6 of the
handoff), which is why LAN development needs a genuinely trusted certificate
rather than a self-signed one clicked past.
